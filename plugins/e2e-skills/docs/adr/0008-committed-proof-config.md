# The proof config is committed once, not rewritten every run

`docs/adr/0007` gave the Proof clip a fidelity contract and implemented the legibility half of it through an **ephemeral** config: Step 7 wrote `.pw-prove.proof.config.ts` next to the project config with the run's effective viewport substituted into `video.size`, and Step 8 hygiene deleted it. Ephemerality was never the point — it fell out of "the file contains a per-run value, so it cannot be a fixture."

That premise was wrong. Everything in the file except the recording size is identical on every run of every project: spread `base`, override `use` with `video: { mode: 'on', size }` and `trace: 'on'`. So each run paid to regenerate a file that only ever differed in two integers — model output to write it, a review surface that looked like a change but never was, and a delete step that had to be remembered or it left litter in the repo. Worse, regeneration is a correctness surface: an agent re-deriving the file each time can re-derive it *wrong* (the recurring failure being a `viewport` key sneaking in, which 0007 exists to forbid), and nothing downstream compares it against the last known-good version.

Decision (pw-prove only): the proof config is a **static, project-agnostic, committed artifact** at `<configDir>/playwright.proof.config.ts`. Written once on the first run in a repo, staged with that run's commit, and reused verbatim by every run after — present means reuse untouched, absent means write it.

- **The one per-run value moves to the command line.** Recording size reads `PW_PROVE_W`/`PW_PROVE_H`, defaulting to 1600×900; the Step-7 proof command always passes the resolved effective viewport. Size is an encoding parameter, so putting it on the invocation rather than in a file is not a loss of fidelity — it is where a per-run parameter belongs. The fidelity contract of 0007 is unchanged in substance: same size, same warm lead, same gated dwell.
- **`viewport` still never appears in it.** Static-and-committed strengthens this rather than weakening it: a reviewer can read the file once and see it, and a later run cannot quietly reintroduce it, because later runs do not touch the file.
- **Structural mismatches become a one-time committed fix.** A project config that is a function export, or has per-project `use` that must win, gets the proof config adapted once and committed. Previously that adaptation was re-derived (and re-risked) on every single run.

Trade-offs weighed. This does commit a file to the user's repo, which 0007 counted as a virtue of the ephemeral approach when it rejected `slowMo`. That virtue was overvalued: pw-prove already commits a spec, a POM and a HAR fixture to the same repo, and a 12-line config that makes every future proof run cheaper is a smaller intrusion than the ones already accepted. Deriving the size from `base.use.viewport` inside the file instead of from the env was rejected — it silently reads a scaffold device-descriptor viewport as deliberate, inverting the 0007 resolution rule in the one place nobody would look. Making the file a shipped template copied by a script was rejected as a script for a file the agent can write inline.

Legacy `.pw-prove.proof.config.*` files from pre-0008 runs are deleted by Step 8 hygiene, which now keeps `playwright.proof.config.ts` instead of deleting it.
