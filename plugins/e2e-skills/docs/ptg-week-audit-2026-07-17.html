Highlights

  • The test runner is being used as a REPL. When the model needs to learn app behavior it writes a throwaway spec (zz-debug.spec.ts, _live-recon.spec.ts…) and runs it — paying a full Playwright boot per question. Worst run: 8 probe specs, 48 invocations, 55 min of CLI time.
  • Model output volume is confirmed as the bottleneck at fleet scale. 8.2M output tokens this week; a median run emits ~350k tokens to deliver 1–3 specs. Browser/driver time is 0.4% of active time — optimizing it buys nothing.
  • The new script pipeline works where it was available. The four Jul 15–16 sessions with preflight → record → host-on-r2 spent 3–5 min in scripts, no film-loop runaways, fewest raw test runs.
  • One silent wrong-pass escaped. A generated test encoded the inverse of the intended CTA behavior and passed; only the user’s eyeball caught it (tilapia, Jul 16).

Improvement plan

Ordered by measured leverage. One theme: move work out of the 62% model bucket into the 15% deterministic bucket, and leave a ledger behind so next week’s audit is a one-liner instead of transcript mining. Aligned Jul 17 via grill session against SKILL.md v1.9.0 — each step below reflects the agreed decision, not the audit’s first draft.

1

Ban the probe-spec REPL — ship a persistent recon probe

Add probe.mjs to the shipped scripts: one long-lived Playwright context that accepts batched commands (goto / click / fill / snapshot / eval) and prints compact accessibility-tree + network summaries. SKILL.md rule: recon questions go to the probe; a *.spec.ts that isn’t a deliverable is forbidden. One browser boot amortized over the whole recon phase instead of 10–40 boots.

pw runs/session 11 → ≤4dolphin-class CLI 55m → ~10m
2

POM inventory in Step 1 — the POMs are the selector map

Aligned: no new artifact. Step 1’s project profile gains a required POM inventory line — existing Page Objects mapped to routes — and Step 5 must extend a matching existing POM instead of writing a new one. Cross-run selector memory stays where it already lives: checked-in, typed POMs plus the Step 5b conventions doc + seed spec.

spec churn 2.7 → ≤1.5 edits/specduplicate POMs per route → 0
3

Leave a run ledger — auditable by construction

Aligned: no files in target repos. Each shipped script prints one PTG_RUN {json} line to stdout (phase, skill version + SHA, duration, exit) — it lands in the session transcript for free — and appends the same line to ~/.ptg/ledger.jsonl. preflight.mjs echoes the version banner. “Audit the skill” becomes cat ~/.ptg/ledger.jsonl; zero target-repo pollution, no hygiene-sweep changes.

audit cost hours → minutesversion drift detectable per run
4

Trace every assertion to the acceptance line it proves

Aligned: enforced inside PTG, not e2e-reviewer. Every generated test carries a // PROVES: <AC quoted verbatim from the Step 2 table> header; Step 6’s YAGNI audit gains the rule — missing or paraphrased = fix before Step 7. No new reviewer pattern ID, no parity ceremony; the check scopes to exactly where the failure class lives (PTG output). Promote to a reviewer pattern later only if it earns it.

wrong-expectation escapes 1/wk → 0
5

Target mode publishes by default

Aligned: PR-mode already has zero gates (81a0c7e) — the audit’s “collapse the gates” framing was stale. The real gap: both no-link incidents were target-mode runs, where Step 8 is opt-in. Fix: a target-mode run that passes Step 7 with HOSTING_READY=yes films + publishes like PR-mode, ending at a watch link. Coverage-gap mode keeps its approval gate and stays film-opt-in.

runs without a published link 2 → 0re-invocations just to publish → 0
6

Token diet rules in SKILL.md

Aligned: two of three rules already exist (b08edf3’s rerun-only-what-failed, full-suite-once) yet tilapia still ran 17× on the current skill — so add the missing line and make the ledger the enforcement. New: no narration between tool calls inside the film/fix loop; write the spec once from the POM inventory — never scaffold-then-rewrite. The PTG_RUN ledger makes runs-per-session a tracked metric instead of an honor rule.

median tokens/run 350k → ≤200kfull-suite runs ≤1/session
7

Fix the chapter-offset bug in the film contract

Aligned: shrunk from “ship a template file” — the watch page already IS a template inside record.mjs, and the drift complaints trace to the stale skill copy (fixed, v1.9.0) plus one real bug: the :0:11 incident — chapter timestamps bunched at the same offset. Fix the chapters.json offset capture in the film-spec contract (offsets must be taken when the chapter starts on screen), and have record.mjs reject a chapter list whose offsets collapse within a few seconds of each other.

bunched-chapter films → rejected at QA gate
8

Recommend a fresh context for PR-proof mode — never auto-background

Aligned: recommend, don’t auto. Step 0 gains: when invoked into an already heavy session, say so and offer a fresh session / background agent as the faster, cheaper path — then continue inline if the user doesn’t take it. Auto-backgrounding was rejected: it silently kills the plan-post-interrupt contract and unsupervises film QA.

mid-session invocations 15/21 → user-informed opt-in
