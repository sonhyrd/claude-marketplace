## On the two noise sources

Neither can reach the URL if the documented capture is used, because both are **stderr** and the marker line is **stdout**:

```bash
BEARER="${AUTH_TOKEN:-}" SCAN="<generated-spec-file>" \
  agent-native vault exec --app <vault-app> --key CLIPS_MCP_TOKEN -- \
  node .claude/skills/pw-prove/scripts/publish-proof.mjs /tmp/pw-prove-manifest.json \
  >/tmp/pw-prove-publish.out 2>/tmp/pw-prove-publish.log
RC=$?
PAGE=$(sed -n 's/^PWPROVE_URL //p' /tmp/pw-prove-publish.out | head -n1)
KEPT=$(sed -n 's/^PWPROVE_PROOF_FILE //p' /tmp/pw-prove-publish.out | head -n1)
```

Separate files, not `2>&1`. The `npm warn Unknown project config` pair from your `.npmrc` (emitted by the `npx`/shim layer) and ffmpeg's banner both land in the `.log`; `sed` reads the `PWPROVE_URL` marker out of the `.out`. `head -n1` on a merged stream is what loses the URL — line 1 becomes an npm warning. Note the script itself runs under `node`, not `npx`, so npm's chatter arrives via the wrapper, not the publish.

Two things I'd keep regardless of noise: branch on `$RC`, not on an empty `$PAGE` (exit 0 with no URL is *undelivered, file kept*; exit 3/6/8/9 is a *gate*, nothing published and no file offered), and take the per-chapter links from the log's `/embed/<id>?t=` lines rather than appending `?t=` to the share URL.
