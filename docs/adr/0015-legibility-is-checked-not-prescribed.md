# Clip legibility is checked, not prescribed: the filming law, framing, and a frame the agent looks at

`docs/adr/0007` gave the Proof clip a fidelity contract — legible size, warm lead, held payoff — and `docs/adr/0008` moved the one per-run value out of the config. Both records specify. Neither *enforces*. A real PR-mode run (`hyrdrocks/nuxt-hyrd-chrysus` #3109) produced five green scenarios, a RED mutation check, a published proof page, and a recording the operator described as showing nothing. Every gate the pipeline owns was green, because no gate looks at legibility.

The failure had two halves, and both were invisible by construction.

**The prescribed dwell was never written.** `code-rules.md` §Clip Fidelity prescribes a `PW_PROVE_CLIP`-gated post-assertion dwell; Step 5 points at it; Step 7 passes `PW_PROVE_CLIP=1`. The generated spec contained no reader for the variable, so the flag was inert. Step 6 audits `// PROVES:` headers and invokes `e2e-reviewer`; neither knows the dwell exists. The same hole covers the viewport pin: a `pinned:` verdict in the Step-4 Assumptions block is *prose*, and nothing compares it against the spec. Step 7's claim that "fidelity is held at authoring time instead" was therefore unbacked — the design is defensible, the missing half was the authoring-time check.

**The contract was one property short.** The clip was correctly sized, warm and held, and still useless: `scrollIntoViewIfNeeded()` moves the minimum distance, so the element under proof landed against the screen edge and a later re-render pushed it off-frame entirely. "Held payoff" was already in the glossary and was read as a duration.

Decision (pw-prove only), in four parts:

- **The filming law.** `PW_PROVE_CLIP` may only ever **add time**, never change what the app is asked to do. Waits are gated; centring, scroll and choice of input method are unconditional and run in CI too. This generalises 0007's own argument — which licensed the dwell solely because, sitting after the terminal assertion, it could not move the verdict — from one *position* to one *class of operation*. It consequently **relaxes** 0007's "one per test, at the very end": a gated dwell may sit at any beat except between an action and the assertion that covers it, where the filmed run would be more patient than CI and a proof would pass where CI flakes.
- **Framing is the fourth property** of the contract, and it is ungated: the element under proof is centred (`scrollIntoView({ block: 'center' })`, at the moment of the hold, not before an intervening re-render), in the committed spec, so CI renders identically.
- **Authoring-time compliance is mechanically checked and blocks Step 7.** `scripts/clip-fidelity.mjs spec` asserts every `test()` carries a gated dwell with its `// JUSTIFIED:` line, and that a `pinned:` verdict produced an actual `test.use({ viewport })`. It **re-derives** the viewport verdict by reading the project config as text — the resolution rule is already textual — *and* takes the agent's declared verdict as an argument; a disagreement is itself a failure, which turns the Assumptions block from unverified prose into a checkable claim. Structural ambiguity refuses rather than guesses.
- **Step 7 extracts one frame per clip at `duration − 0.5s` and the agent looks at it.** An illegible frame is diagnosed — payoff not held, element off-frame, still booting — the matching fix is applied to the committed spec or the warm lead, the Step-6 check re-runs, and the run re-films **once**. A second illegible frame publishes with an explicit warning rather than stopping: a bad clip is not a failed test.

Trade-offs weighed. A **`publish-proof.mjs` legibility gate** (a frame-difference heuristic over the final seconds) was rejected: its failure mode is dropping a good proof on a heuristic, and a gate that trips aborts the whole recording. Inspection that informs the agent is strictly safer than a gate that vetoes the artifact. **Gated input substitution** — a `PW_PROVE_CLIP`-gated `pressSequentially` replacing an atomic `fill()`, the fix actually used on #3109 — was rejected as a violation of the filming law: it swaps one `input` event for N keystroke events *before* the assertion, so on any debounced or per-key-validated field the filmed run drives software CI never drives. This is the viewport-axis argument transplanted to the input axis, and the same silent-always-pass family. Making the typing visible was dropped altogether: unless the acceptance criterion is about entering data, the evidence is the state change, and the clip holds on the filled field instead. An **ungated `pressSequentially({ delay })`** was rejected separately — the delay is a per-keystroke fixed sleep every CI run pays forever, which is smell #9's cost profile re-entering through the front door. Making the check an **e2e-reviewer pattern (#24)** was rejected: the rule is meaningless outside pw-prove and would flag every ordinary Playwright repository, and patterns are a stable public surface judged against other people's specs.

This narrows, rather than contradicts, `SKILL.md` Step 7's "nothing measures the finished webm — by design". No *gate* measures it. Nothing is edited, no post-processing pass returns, and the external dependency 0006 deleted stays deleted — `ffmpeg`/`ffprobe` are already required by `publish-proof.mjs` and already probed by `preflight.mjs` as `VIDEO_TOOLING`. Where they are absent the frame extract skips with a stated line, matching the publish-skip precedent, and never fails the run.
