# A pw-prove run delivers ONE proof page, not N clip links

`docs/adr/0006` made the proof evidence a byproduct of the single Step-7 run and deleted PTG's whole film apparatus for pw-prove: no second run, no chapters, no contact sheet, **no watch page**. `docs/adr/0007` then held the surviving artifact — the per-AC webm — to a fidelity contract, because an unwatchable clip buys nothing.

Both records reasoned about *a* clip. A real five-AC run showed what N of them look like in a PR: five bare `.r2.dev/...webm` links in a table, each opening a raw video in a new tab with no title, no context, and no way back to the next one. The reviewer's job — watch the proof of this change — was spread across five tabs and five decisions about whether the next one is worth opening. The artifact passed 0007's contract clip by clip and still failed as evidence in aggregate, which is the same class of oversight 0006 made and 0007 named.

Decision (pw-prove only): a run publishes **one proof page** — `host-proof.mjs` uploads every clip under a single key prefix and writes an `index.html` beside them with an AC rail, auto-advance between clips, and a `#<ac-slug>` anchor per AC. The PR comment leads with that one link; the AC table's rows deep-link anchors *inside* it.

- **Nothing that 0006 removed comes back.** No second run, no ffmpeg, no chapter sidecar, no contact sheet, no film-QA gate. The page is assembled from the clips the Step-7 run already produced, by the same script call that was already uploading them. The cost is one extra `wrangler put` for a ~4KB HTML file.
- **The gates are unchanged and now cover more.** Every object — each clip and the page — publishes through `host-video.mjs`, so degenerate-key (2), empty-recording (3) and token-leak (6) apply per clip. A gate tripping on any clip aborts the whole page: a proof page with a hole in it reads as complete evidence while being incomplete, which is the silent-always-pass shape in artifact form.
- **Clips are referenced relatively** (`./<slug>.webm`), so the page carries no bucket domain and survives a bucket or public-host change. Per-clip URLs still exist and are printed on stderr; they are no longer what the PR comment leads with.
- **An AC is untrusted text** — it comes from a diff, a ticket or a PR body. It reaches the page as `textContent`, never `innerHTML`, and `<` is `\u`-escaped inside the embedded JSON so an AC containing `</script>` cannot close the script element. The page is published on a domain shared with other proofs; treating an AC as markup there is a real hole, not a theoretical one.

Trade-offs weighed. Inlining the clips as data URIs (PTG's approach for its single film) was rejected: five base64-inflated webms make a page tens of MB, and sibling objects keep each clip individually cacheable and linkable. Concatenating the clips into one video was rejected outright — that is ffmpeg and a second processing pass, exactly what 0006 removed; auto-advance gives the "watch it as one pass" property without touching a frame. Keeping the N-link table as an option was rejected as the thing being fixed: two shapes means the weaker one keeps getting emitted.

This is a deliberate partial reversal of 0006's "no watch page" line, and only that line. The rest of 0006 — evidence as a byproduct, one run, no film step — is what makes this page cheap enough to be worth having.

> **Partially superseded by [`0012`](0012-publish-to-clips-stream-copy-concat.md).** Only the no-concatenation line above is superseded, on a re-run measurement: stream copy decodes nothing, so it is a byte copy rather than a processing pass. The *goal* of this record — one link, an AC rail, per-AC deep links, watch-as-one-pass — is preserved and delivered natively by Paul Clips; the hand-built page, its key prefix and `host-proof.mjs` / `host-video.mjs` are gone.
