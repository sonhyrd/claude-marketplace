# pw-prove publishes ONE Clips recording — stream-copy concatenation, and only 0009's no-ffmpeg line is superseded

`docs/adr/0009` gave a pw-prove run one link instead of N: `host-proof.mjs` uploaded every clip under one key prefix and wrote an `index.html` beside them with an AC rail, auto-advance and a `#<ac-slug>` anchor per AC. That record also rejected the alternative outright: *"Concatenating the clips into one video was rejected outright — that is ffmpeg and a second processing pass, exactly what 0006 removed."*

Decision (pw-prove only): the run publishes to **Paul Clips**. `publish-proof.mjs` probes each clip, gates it, concatenates the clips by **stream copy**, mints a short-lived scoped token and POSTs the whole recording in one request; the run reports one `https://clips.paulsjob.ai/share/<id>` link. `host-proof.mjs` and `host-video.mjs` are deleted, and `wrangler` leaves the pw-prove path entirely.

**This supersedes exactly one line of 0009 — its no-concatenation constraint. Nothing else.** 0009's *goal* is preserved and now delivered natively: one link, an AC rail (chapters on the scrubber), per-AC deep links (timestamps), and playback that runs through every criterion as one pass. **ADR 0006's substance is untouched:** no second run, no film step, no chapters sidecar, no contact sheet, no Film QA gate; the evidence is still the byproduct of the single Step-7 proof run. **ADR 0007's fidelity contract is untouched**, and now provably so — see the measurement.

The constraint was lifted by measurement, not preference. 0009 costed concatenation as a *processing pass* against *"one extra `wrangler put` for a ~4KB HTML file"*. Both halves of that comparison changed:

- **It is not a processing pass.** The concat demuxer with `-c copy` muxes the inputs' existing packets into one container: nothing is decoded, so no frame is touched and the [Clip fidelity contract](0007-proof-clip-fidelity.md) survives bit-for-bit. Re-measured on a **heterogeneous** set while implementing — three VP8 1600×900 25fps clips of different content and different lengths (7.200s `testsrc`, 11.440s `smptebars`, 4.360s `testsrc`) — the output reported exactly **23.000s** against an input sum of 23.000s, in **0.09s** of wall clock, at 1,488,035 bytes against 1,488,987 bytes of input. The only bytes that changed are container headers. An earlier measurement on a real proof clip (VP8, 1600×900, 25fps, 34.680s, 2.1 MB) concatenated with itself reported exactly 69.360s.
- **The alternative is no longer a 4KB HTML file.** Publishing per-clip to Clips would hand back N share links — the exact N-link table 0009 was written to abolish.

What the deletion buys is the point: ~100 lines of inline player CSS and JavaScript, the HTML-escaping of untrusted AC text, the slug deduplication, the key-prefix scheme and the whole bucket dependency all go, replaced by a product surface that already renders chapters as scrubber markers and honours timestamp deep links. The AC-as-untrusted-text hazard 0009 called *"a real hole, not a theoretical one"* stops being this repository's problem to solve.

**The gates moved with the mechanism, and two are new because the mechanism is new.** Degenerate-key (2) is retired — Clips assigns the identifier, so this script builds no object name and there is nothing left to refuse. Empty-recording (3) carries over unchanged. Token-leak (6) carries over and is **widened** to the recording title, its description and every chapter title: the ACs now travel as JSON to a recording that is public by default, so a credential pasted into an AC is a live leak path a byte scan alone would miss. Two are added, and both read probe data already gathered for the chapter offsets, so neither costs a subprocess:

- **Homogeneity (8)**, before concatenation. Stream copy cannot reconcile a disagreement it never decodes. Measured: concatenating a 1600×900 clip with a 1280×720 one **exits 0, prints no error**, and yields a 12.200s file whose second half is 720p packets inside a stream declared 1600×900 — a silent-always-pass in artifact form, which is precisely why this is refused rather than detected afterwards.
- **Duration reconciliation (9)**, output against the sum of its inputs. Chapter offsets are cumulative input durations; if the totals diverge, every chapter after the divergence points at the wrong footage, and a reviewer sent to the wrong second reads it as the criterion failing. The allowance is a per-clip container-rounding one, not a percentage of the run — a fraction of a percent of a 40-minute run would swallow an entire missing clip.

A gate trip publishes nothing, names itself, **and withholds the local file** — 0009's principle that partial evidence is worse than none, extended: a gated artifact is *wrong*, not merely undelivered, and a video known to be wrong is never handed over as evidence.

**Delivery failure is the opposite posture.** A 500, a refused connection or a rejected credential leaves the run passing (exit 0): the proof is the passing test plus the mutation verdict, and a run never fails over undelivered evidence. The concatenated video is kept at a stable path, printed on a `PWPROVE_PROOF_FILE` marker line and **exempted from the Step-8 hygiene sweep**, so the proof can be attached by hand. That restores a property the R2 design had incidentally — a failed page still left the clips uploaded — which this design would otherwise lose, since nothing leaves the machine before the single POST.

Trade-offs weighed. A long-lived issued token was rejected: with no token-id denylist on the receiving side, revocation costs a secret rotation either way, so a five-minute token minted per publish is strictly better than a bearer sitting on disk. A bespoke shared-secret header was rejected: it would invent auth beside a working scheme and give the receiving adapter no verified identity to scope by. Re-encoding, trimming or any transcode is rejected and stays rejected — that would genuinely reintroduce what 0006 removed. Keeping the R2 path as a fallback was rejected for 0009's own reason: two shapes means the weaker one keeps getting emitted.

`playwright-test-generator` is deliberately unmoved. It keeps its watch page and its bucket, so `wrangler` remains a bundle dependency for that skill; its port also means finding homes for the contact sheet and Film QA gate vocabulary, which is a separate conversation. One skill is proven on this path first.
