# The Proof clip has a fidelity contract: legible size, warm lead, held payoff

`docs/adr/0006` made the proof evidence a byproduct of the single Step-7 run, and justified keeping a *native video* — rather than dropping to a trace-only artifact — on the grounds that "a clickable per-AC clip in the PR is worth the one extra upload call." That reasoning is sound, and it carries an obligation nobody checked: the clip has to be watchable.

It wasn't. A real PR-mode run produced a clip that was ~800×450 (the app's own UI text illegible), spent most of its runtime on the dev server compiling the route, and flashed the actual interactions past in well under a second. Reviewers ignored it or re-ran the spec locally, which is exactly the outcome the upload was supposed to buy off. "Mostly loading" and "too fast" turned out to share one root: the proof is hermetic and short, so a fixed boot cost necessarily dominates and the informative frames are a sub-second slice.

Decision (pw-prove only): the Proof clip is **reviewer-facing evidence held to a fidelity contract**, and failing it is a defect, not an accepted trade-off. Three changes, none of which reintroduces anything 0006 removed — no second run, no chapters, no contact sheet, no watch page, no ffmpeg:

- **Legible size.** Playwright's default recording size is the viewport scaled into an 800×800 box. The ephemeral proof config sets `video.size` equal to the **effective viewport**, so the clip is never downscaled. `size` is an encoding parameter only — it does not change rendering.
- **The viewport pin lives in the *committed* spec.** Rendering viewport affects layout, so pinning it only in the throwaway proof config would mean locator healing, the hermetic audit and the mutation check all ran against a rendering CI never produces — a viewport-axis instance of the silent-always-pass family this bundle exists to prevent. Committing the pin makes the proof run and the CI run render identically by construction. The project's committed `playwright.config` is still never edited.
- **A deliberate project viewport wins; scaffold boilerplate does not.** Only an explicit `viewport:` key counts as deliberate. A viewport arriving solely from a desktop device-descriptor spread is scaffold default and gets pinned over — nearly every scaffolded config spreads `...devices['Desktop Chrome']` with its 1280×720, so reading that as a project decision would mean the pin essentially never fires. A mobile or non-desktop descriptor is always respected.
- **Warm lead.** One request against the route under proof immediately before filming, so the clip opens on a compiled app. One request, no extra test run, no new dependency. *(Amended by `docs/adr/0013`: implemented as a `curl`, this warmed the document but not the client module graph, and a Vite-family app paid its 25s boot inside the recording anyway. The request is now a real browser load — `probe.mjs warm` — from a process the proof run does not film.)*
- **Held payoff, via an env-gated dwell in the committed spec.** PTG holds its payoff using a throwaway film spec; pw-prove films the committed one and its own rules forbid fixed sleeps (#9, P1). The resolution is a `waitForTimeout` **after the terminal assertion**, gated on `PW_PROVE_CLIP` — set by the proof run alone. Because it follows the terminal assertion it cannot move pass/fail, so proof and CI stay semantically identical despite the conditional; CI never sets the variable and pays nothing as proofs accumulate. A `// JUSTIFIED:` line above it suppresses #9 across all three scanner tiers, so no scanner or corpus change is needed. *(Amended by `docs/adr/0015` on the placement clause only: "one per test, at the very end" is relaxed to "any beat except between an action and the assertion that covers it", under the filming law — `PW_PROVE_CLIP` may only ever add time. That record also adds a fourth property, **Framing**, and makes compliance with this contract mechanically checked at authoring time instead of assumed.)*

Trade-offs weighed. Post-processing the recording to trim the boot lead was rejected: it re-adds an external video dependency and an editing step 0006 deleted, and an edited clip is no longer a faithful recording of the run. `slowMo` in the ephemeral config was rejected in favour of an explicit, reviewable artifact in the deliverable — it commits nothing to the user's repo and remains the fallback if the shipped-sleep tension proves uncomfortable in practice. An ungated dwell was rejected as a permanent, accumulating CI cost. Delivering the trace as a second artifact stays rejected per 0006.

The acknowledged tension: this ships a documented instance of a smell the bundle sells a scanner to detect. It is legal under the project's own `// JUSTIFIED:` contract, it never runs in CI, and it is the only such instance — but it is a real cost, consciously paid.

This record is deliberately **additive rather than an amendment to 0006**. 0006 optimised away a second run and a great deal of ceremony, which was correct; what it did not do was check whether the surviving artifact could still do the job it claimed for it. Keeping both records preserves that oversight instead of erasing it.
