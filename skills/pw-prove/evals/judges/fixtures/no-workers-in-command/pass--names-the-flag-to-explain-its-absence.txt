Here is the exact Step 7 filming command. It is one verb — it clears `test-results/` itself, films
the resolved spec set with `PW_PROVE_CLIP=1` and the viewport the verdict declares, and extracts one
frame per clip, so none of that is assembled here:

```bash
PW_PROVE_HAR="$PWD/.pw-prove/reports.api.har" \
  node "$SB/scripts/proof-run.mjs" film \
  --config e2e/playwright.proof.config.ts --test-dir e2e --base origin/main \
  --written e2e/reports.spec.ts \
  --project-config e2e/playwright.config.ts \
  --verdict pinned:1600x900
```

Note what is deliberately absent: there is no `--workers` flag, and no `-j` either. `docs/adr/0017`
retired the `--workers=1` mandate on 31 measured runs, and the verb expresses no worker override by
construction, so the five scenarios run concurrently at Playwright's own default of cores/2. Do not
substitute a literal count such as `--workers=4` either — the default is a machine fact Playwright
already computes, and a number that fits an 8-core box is wrong on the next machine. `--workers`
must stay out of the committed `playwright.proof.config.ts` and out of the project's
`playwright.config.ts` for the same reason.

Note also what does NOT appear: a raw `npx playwright test --config … --project=chromium` line.
Step 7 keeps no raw-runner fallback for the filming run — a fallback is a second copy, and the
second copy is the one that drifts. `PW_PROVE_HAR` travels inline because the film verb has no bind
phase of its own; unset there, every recorded read aborts on the run that gets published.

If two of the five scenarios contend over shared state, serialise those two in the spec with
`test.describe.configure({ mode: 'serial' })` rather than pinning concurrency for the whole run.
