`SERVE_CAUSE=no-announcement` says exactly what it says: the log names **no listening origin**. So
there is no port to have got wrong — the port could never be read in the first place. Combined with
the crash the phase printed, this is the server or the built output, not a mismatch.

The server's own error is the finding:

```
Error: Cannot find module '/repo/.output/server/index.mjs'
```

The preview command is being pointed at an output path that does not exist. So:

1. **Confirm what the build actually produced.** `BUILD=ok` means the build succeeded, not that it
   wrote `.output/server/` — this project's build may emit somewhere else entirely, or emit a
   static output with no server entry at all.
2. **Start the project's own preview command against that output**, then re-run the serve phase.

What I rule out, and why:

- **A shifted port.** Nothing announced an origin, so there is no shifted number to find. Scanning
  other ports would at best find some *other* process.
- **Other loopback forms.** `[::1]` versus `127.0.0.1` matters when something *is* listening and
  the family is wrong. Nothing is listening.
- **Re-running the serve phase on a longer budget.** The process crashed; it is not slow to start.
  More time produces the same stack trace.
- **Re-running the build.** It already passed, and a build failure would have been reported as
  exit 5 with its own standard error, not as a serve-phase no-announcement.
