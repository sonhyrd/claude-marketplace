## The `dev`-script trap

The package only has `dev`, but **the proof target is the built app** — there is no development-server path. So:

- Bring-up is `preflight.mjs config build` with `BUILD_COMMAND` = the Nuxt build (`nuxt build`, added as a `build` script if the repo genuinely lacks one), `APP_ROOT` = the app root, `BUILD_OUTPUT=.output`. The phase **refuses without a `BUILD_COMMAND`** rather than silently serving whatever is listening, which is exactly the failure mode a `dev`-only package invites.
- The server is `nuxt preview` against `.output`, started as a harness background task on a **freshly allocated free port** — 3100 is a preference, not a reservation, and the port that counts is the one the server announces in its log. `preflight.mjs serve` with `SERVER_LOG` reads that announcement; the summary's `BASE_URL=` line is the origin I carry everywhere afterward.
- The scaffolded config's `webServer` (running `dev`) is precisely what would defeat this. `playwright.proof.config.ts` sets **`webServer: undefined`**, so the proof run cannot boot a dev server behind my back when the config's URL doesn't answer. Before Step 6 I curl the literal `use.baseURL`/`webServer.url` string the runner will dial and, if the announced port differs, set `PLAYWRIGHT_BASE_URL` to the reachable form and carry it on **every** invocation — tsc-adjacent runs, proof run, heal runs. Each is a fresh environment.

## Path to a green Step 7

1. `npx --no-install tsc --noEmit -p e2e/tsconfig.json` → 0 errors.
2. `.pw-prove/` into `.git/info/exclude`, then `har-scrub.mjs bind e2e/onboarding.api.har --out .pw-prove/onboarding.api.har --origin "$BASE_URL"`, export `PW_PROVE_HAR`. Replay matches on exact URL equality, so skipping the bind makes *every* read abort and reads as a broken app — that's the first thing I'd check if the run comes back all-aborted.
3. `playwright.proof.config.ts` written once next to `playwright.config.ts` (spread base, `webServer: undefined`, `video: {mode:'on', size}`, `trace:'on'`), staged as a deliverable.
4. `rm -rf test-results`, then the proof run with `PW_PROVE_CLIP=1 PW_PROVE_W=1600 PW_PROVE_H=900`. **Effective viewport verdict: `pinned: 1600x900`** — I author the config myself and it carries no `viewport:` key, so the pin goes in the committed spec as `test.use({ viewport: { width: 1600, height: 900 } })`, and Step 6's `clip-fidelity.mjs spec … --verdict "pinned:1600x900"` must exit 0 before this run happens.
5. Failure loop ≤3 attempts, healing by intent off a fresh probe snapshot, `-g` the failing test only, full spec once at the end. I record each attempt's failure signature (error class + failing locator) and **stop at the first repeat** rather than paying for a third identical timeout; loop exhausted → `playwright-debugger` on `playwright-report/`, then the target-mode stop report — never a fabricated pass.
