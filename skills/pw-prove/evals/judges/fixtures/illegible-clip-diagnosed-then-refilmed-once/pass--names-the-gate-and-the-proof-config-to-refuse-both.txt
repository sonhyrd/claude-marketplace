First, the inspection itself — what each frame shows. The film verb extracted them for me and the
summary says which exist, so this is reading rather than a command I run:

- **Clip 1** — the saved banner, centred and settled. Legible.
- **Clip 2** — the saved banner on the second record, centred and settled. Legible.
- **Clip 3** — the record list with the success toast cut off against the right edge of the frame.
  Illegible.

**I diagnose clip 3 before anything is re-filmed.** The subject is not missing and not blurred; it
sits against the frame edge, so this is element-off-frame. Re-filming without a fix is pointless
here — the run is deterministic and would reproduce the same frame.

**The fix**, in the committed spec, at the moment of the hold:

```ts
await toast.evaluate((n) => n.scrollIntoView({ block: 'center', inline: 'center' }));
// JUSTIFIED: payoff dwell — holds the asserted toast long enough to read.
if (process.env.PW_PROVE_CLIP) await page.waitForTimeout(1200);
```

Two things this is deliberately **not**:

- It is **ungated**. I do not put the scrollIntoView behind PW_PROVE_CLIP. The filming law is that
  the variable may only ever add time, and framing is not time — a gated scroll would mean CI runs a
  differently-positioned page from the film.
- It goes in the **committed spec**, not the proof config. The proof config carries recording
  settings; a framing change that only exists there is a change CI never sees.

**Then the re-film, which is the same `proof-run.mjs film` command I already ran.** I do not clear
`test-results/` by hand and I do not run `clip-fidelity.mjs` beside it — the verb does both. It
re-runs the clip-fidelity audit over the edited spec as its **precondition** (an edit that moved the
dwell can have dropped its `// JUSTIFIED:` marker), clears the results directory itself, films again,
re-extracts the frames, and counts this run as the re-film:

```bash
PW_PROVE_HAR="$PWD/.pw-prove/records.api.har" \
  node "$SB/scripts/proof-run.mjs" film \
  --config e2e/playwright.proof.config.ts --test-dir e2e --base origin/main \
  --written e2e/records.spec.ts \
  --project-config e2e/playwright.config.ts \
  --verdict pinned:1600x900
```

Exit 12 would mean the edit broke the fidelity contract rather than fixing the frame; exit 13 would
mean the edit moved the spec set out from under the audit's network finding, and I would run the
audit verb again.

Which attempt this is I **read** rather than recall: the new summary carries `films: 2` and
`publish_with_warning: true`. So if the second frame is still illegible I **publish it with an
explicit warning** — `Clip 3 — illegible (element off-frame), published with warning` — rather than
stopping. A bad clip is not a failed test, and I do not re-film a second time chasing it.
