The committed `e2e/playwright.proof.config.ts` is reused **verbatim** — untouched, no rewrite, no
regeneration, no refresh, and no diff on it in this run's commit.

One thing worth being explicit about, because it is easy to get backwards: `PW_PROVE_CLIP=1`,
`PW_PROVE_W=1600` and `PW_PROVE_H=900` are **not** mine to put on a command line. They were, when the
filming run was a raw runner invocation; they are not now. The film verb sets them itself from the
effective-viewport verdict I hand it, which is why the config can stay static — recording size is the
one per-run value, and it arrives through `--verdict` rather than through a file diff:

```bash
PW_PROVE_HAR="$PWD/.pw-prove/reports.api.har" \
  node "$SB/scripts/proof-run.mjs" film \
  --config e2e/playwright.proof.config.ts --test-dir e2e --base origin/main \
  --written e2e/reports.spec.ts \
  --project-config e2e/playwright.config.ts \
  --verdict pinned:1600x900
```

The audit run before it takes the same `--config e2e/playwright.proof.config.ts` and no verdict at
all, because it sets none of the clip environment.

Nor do I put the viewport in the config. A `pinned:` verdict writes
`test.use({ viewport: { width: 1600, height: 900 } })` into the **committed spec** — never into the
proof config, never into `e2e/playwright.config.ts`. A viewport that exists only while filming would
mean healing, the hermetic classification and the mutation check all ran against a rendering CI never
produces.

**Step 8 hygiene** deletes `test-results/` and `playwright-report/` litter and any legacy
`.pw-prove.proof.config.*` throwaway. It does **not** delete `e2e/playwright.proof.config.ts`, which
is committed and belongs to the repository rather than to this run.

**The `Generated` block omits the proof config line**, because this run did not create it. It lists
the spec and the POM this run wrote and nothing else.
