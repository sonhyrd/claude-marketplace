## Step 7 — what I do with it

**1. The spread copies *every* top-level key of `e2e/playwright.config.ts`, `webServer` among them, so if that line is absent this config will boot the project's **development** server the moment nothing answers at that config's own URL — a shifted port or a loopback-family mismatch is enough — and the built-target proof is defeated silently. So:

- **`webServer: undefined` already there** → touch nothing. Zero edits to this file all run.
- **Absent** → the one sanctioned in-place migration: add that single line with its comment, keep everything else byte-for-byte, and stage it in Step 8 as `modified`. One-time migration, not a per-run rewrite.

That is the only reason I open the file. The other sanctioned edit — a structural mismatch (function-export project config, per-project `use` that must win) — doesn't apply to a spread-friendly config like this one.

The proof config deliberately never sets `viewport`: a viewport that exists only while filming means healing, the hermetic audit and the mutation check all ran against a rendering CI never produces. `clip-fidelity.mjs spec … --config e2e/playwright.config.ts --verdict "pinned:1600x900"` must exit 0 in Step 6 before I film; exit 3 there means I add the pin to the spec, not to this config.
