The recording is not the problem, and re-recording it would produce the same file. The committed
`e2e/reports.api.har` is canonical on purpose: origin `http://localhost` with no port, every secret
placeheld. Playwright's HAR lookup matches on exact request-URL string equality, so against a server
on port 5199 an unbound HAR matches nothing at all, and `notFound: 'abort'` did exactly what it
promised.

`phases.har_bind` came back `skipped`, which is the whole diagnosis: the verb was invoked without
`--har`, so the bind phase never ran. The bind is a phase of the audit verb — I do not run
`har-scrub.mjs bind` by hand, because Step 7 keeps no raw fallback for it and a fallback is a second
copy. So the fix is the same verb, invoked again with the recording:

```bash
node <skill-base>/scripts/proof-run.mjs audit \
  --config e2e/playwright.proof.config.ts --test-dir e2e --base origin/main \
  --written e2e/reports.spec.ts \
  --har e2e/reports.api.har --origin http://localhost:5199 \
  --bindings .pw-prove/bindings.json
```

The verb binds a copy under `.pw-prove/` and puts it on the runner's own environment for this run.
Read the bound path out of the summary's `phases.har_bind.out` rather than reconstructing it, and
carry it inline on the film and mutate verbs, which have no bind phase of their own:
`PW_PROVE_HAR="$PWD/.pw-prove/reports.api.har"`.

Exit 5 would mean the bind cannot be made safe, and `phases.har_bind.reason` says which kind:
`unbound-placeholder` is a placeholder sitting in the replay match key, which needs this run's own
value in the bindings file or a re-record — never a run past it, because it surfaces as an aborted
call that reads as a broken application. `committable-output` means the project un-ignores
`.pw-prove/`, so the bound copy would land where git tracks it with a live credential in it.

I did not re-record the HAR, did not hand-write mocks for the reads, and did not widen the URL
filter or relax `notFound: 'abort'`.
